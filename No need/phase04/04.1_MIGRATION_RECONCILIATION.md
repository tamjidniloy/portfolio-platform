## Important: what is still blocked

The owner has **not** ratified the exact SRS v1.1, FR-040 MFA, final auth tables, final API and privacy retention. Original Phase 03 candidate SQL has `auth_challenges` and password columns, reflecting emailed OTP draft requirements. NIST SP 800-63B-4 prohibits email as out-of-band authentication. **Technical validation of the original SQL does not approve that authentication design.**

**Recommendation requiring the owner's explicit approval:** WebAuthn/passkey-first, user verification, at least two registered owner passkeys where possible and offline one-use recovery codes; password+TOTP only if expressly selected as a vetted fallback. That decision requires a revised auth schema and OpenAPI; do not deploy current emailed-challenge routes unchanged.

Other decisions: approve the candidate v1.1 SRS and all 76 requirements with exceptions, define retention for contact, media, audit, backups and revisions, select canonical Work route `/projects` (SRS/Phase 03) rather than current prelaunch `/work`, review schema field sizes, privacy, versioning/idempotency and migration library selection. The proposed production migration strategy is reviewed immutable SQL migrations with an independently privileged migration role; a maintained npm tool such as `node-pg-migrate` remains a candidate for production. The small `pg`-only runner in this PR is specifically for **disposable candidate validation** and does not substitute for owner-approved final migrations.

## Test on a disposable Windows/PostgreSQL 16 instance

The existing Windows WebStorm setup guide creates `devfolio_dev` and `devfolio_test`. Those are **not** permitted for experimental Phase 03 candidate migration.

Create one extra disposable database as a privileged PostgreSQL administrator if you wish to run candidate tests yourself:

```sql
CREATE DATABASE devfolio_candidate_migration_ci OWNER devfolio_dev;
```

Then in a PowerShell session **without committing passwords**:

```powershell
$env:CANDIDATE_MIGRATION_DATABASE_URL = "postgresql://devfolio_dev:YOUR_URL_ENCODED_SECRET@127.0.0.1:5432/devfolio_candidate_migration_ci"
npm run db:test:migrations
npm run db:migrate:candidate
Remove-Item Env:CANDIDATE_MIGRATION_DATABASE_URL
```

These commands are optional; they are never required for regular `npm run dev`, `npm run start`, `npm ci` or `/readyz`. The separate CI job always exercises these on an ephemeral Linux runner.
