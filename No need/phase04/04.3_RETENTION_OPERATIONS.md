# Release 1 retention and deletion operations

The 19-table R1 DB has a compatible additive `0004_contact_legal_hold.sql` migration. Release 1 defaults approved by owner: contact until `retention_until` (nominal 90 days), challenge expiry +24h, expired/revoked session +30d, used/revoked recovery codes +30d, replay/idempotency expiry, orphan staging media +24h, processed outbox +30d, audit +365d. **Content revisions remain retained** pending a reviewed referentially safe deletion procedure. Contact legal hold is respected when `legal_hold_until > now()`.

`npm run ops:retention:plan` uses the separately privileged `RETENTION_DATABASE_URL` (never the public reader). The destructive `npm run ops:retention:apply` requires exact database confirmation via `RETENTION_APPLY_CONFIRM`. Production further requires explicit `ALLOW_PRODUCTION_MIGRATIONS=true`. Queries are transactional, locked, and report row counts. Do not run a retention sweep before policy/notice/legal confirmation. The operator must configure a trusted native scheduler (for example Windows Task Scheduler) separately; this repository does **not** self-schedule background jobs.

**Limit:** external media object deletion, provider-side backup expiration (30-day retention), legal retention review, and actual real production scheduling require infrastructure integration. The database sweep cannot delete external files or hosted backups.
