# Phase 04.4 — Media, Contact, Integrations and Privacy

**Scope:** P4-036–P4-044. Engineering implementation in `feat/phase04-4-media-contact-integrations`; contract targets API-R1 (37 operations), DB-R1 original 19 tables, four previous migrations and new additive `0005_media_contact_outbox.sql`.

## Media storage

- `@aws-sdk/client-s3` + `@aws-sdk/s3-presigned-post` exact pinned version, using default credential provider chain. Supports AWS S3-compatible object storage (Cloudflare R2 compatibility requires real provider smoke).
- Provision an existing private bucket with **Block Public Access**, no public-read ACL; enable server role minimum `PutObject`/presigned-post creation, `HeadObject`, `GetObject`, `DeleteObject` only for the private staging prefix. All keys generated server-side as `private/staging/<UUID>/<random>`.
- CORS must allow your **exact** approved portfolio HTTPS origin, `POST`, and the request headers required for signed multipart uploads. Do not allow public `GET` or arbitrary origins.
- From owner `/admin/media` compute SHA256 in browser, request `POST /api/v1/admin/media/intents` with name/MIME/size/digest, POST multipart directly to signed URL (5-minute expiry), then `POST /api/v1/admin/media/{id}/finalize`. Server HEAD + bounded byte GET verifies exact content size, MIME magic bytes and SHA256 before ready.
- Only PNG/JPG/WebP/PDF at 1–8 MiB. **No SVG, JS, HTML or executable uploads**; PDFs remain private. Antivirus/AV scanning, content moderation and public asset transformations/delivery require real provider integration before a public file-serving endpoint is approved.
- Add up to eight `mediaIds` to a private content revision payload. The database links only `ready` media owned by that actor to the immutable revision; retiring referenced assets returns conflict. Retirement/rejection creates a durable physical deletion event; no public object read is granted by upload or publication.

## Contact and consent

- Disabled until `CONTACT_ENABLED=true` and owner private `site_private_config.contactEnabled=true`. Configure **real reviewed** `CONTACT_NOTICE_VERSION` and strong private `CONTACT_IP_PEPPER`; don't commit secrets.
- React Router `/contact` posts JSON to `POST /api/v1/contact`. Exact origin, explicit consent/notice version, trap field, max 120-character name/254-character email/5000-character message. Rate limit by salted IP digest, advisory transaction lock, 3/15m and 10/24h, no raw IP in database.
- A successful **202** means contact message and `contact.notify` event committed to the same PostgreSQL transaction; it does **not** mean a notification was sent. Owner inbox at `/admin/messages`; deletion scrubs body, sender email and IP digest, cancels unsent email, and refuses active legal hold.
- Contact cannot be activated until consent policy and contact text are reviewed and real privacy contact channel is available. Infrastructure reverse proxies must be configured so the true client address is available without trusting spoofed headers. CI uses socket IP only.

## Email, CDN purge and dead letters

- `EMAIL_PROVIDER=resend` uses verified sender domain, `RESEND_API_KEY`, destination `CONTACT_OWNER_EMAIL`, text-only notifications, and deterministic `Idempotency-Key`. Raw content is read only at send time from private `contact_messages`; outbox `safe_payload` is empty for notifications.
- `CACHE_PURGE_MODE=no-store` (default) serves every dynamic response with `Cache-Control: no-store` and assumes no externally forced CDN cache. Optional `cloudflare` requires your own Cloudflare zone/token and exact `CMS_PUBLIC_ORIGIN`. The worker purges affected public URL/list/sitemap after publish/unpublish; failure is retried.
- `npm run ops:outbox:once` uses separately privileged `OUTBOX_DATABASE_URL` and exact `OUTBOX_RUN_CONFIRM`. Bounded leased claims, max 5 attempts, exponential retry, `dead_lettered_at` and non-PII error codes; CLI exits nonzero when DLQ needs operator intervention. **Configure a separate real scheduler and alert channel** (e.g. Windows Task Scheduler every minute + monitoring on nonzero exit). No GitHub CI job contacts live providers and no code claims delivery success without provider acknowledgement.
- Email-provider idempotency windows vary; physical delivery may require reconciliation after long outages. Never treat outbox retry as mathematically exactly-once external effect.

## SEO and retention

- Canonical URLs are computed from the configured trusted public origin, not attacker-provided Host. Public pages render canonical and Open Graph metadata where there are published snapshots. Empty/unpublished content remains noindex. `GET /sitemap.xml` is published-only; `GET /robots.txt` disallows owner routes.
- Existing retention sweep now **marks orphan staged media as rejected and queues deletion** rather than erasing the only storage key. Contact retention defaults to 90 days, audit 365 days, legal holds protected. Use `npm run ops:retention:plan`, then operator-approved `...:apply` with exact database name confirmation. Retention schedules and external bucket lifecycle must be set up with the chosen provider.
- Security check: no raw private media, S3 key, contact body/email, passkey secret or API key is returned in a public API. Anonymous owner media/messages/audit requests are rejected.

## Configuration and acceptance

Required env flags (all default OFF): `CMS_API_ENABLED=true`, `CMS_AUTH_ENABLED=true` with real passkey, `MEDIA_ENABLED=true`, `CONTACT_ENABLED=true`. Separate runtime and public DB credentials already required. Storage and provider values are shown in `.env.example`; do not store credentials in repo/GitHub issue/CI logs.

**Verified automatically only after successful CI:** release migration `0005`, media/consent/outbox/SEO/authorization/retention mocks with PostgreSQL, existing CMS and WebAuthn tests, SSR build and smoke. **Pending real environment:** connect chosen S3 bucket, verified Resend domain, Cloudflare zone if applicable, run browser-upload/CORS and actual provider delivery/retry, WAF abuse/load tests, deletion/retention scheduler and privacy review, WCAG and real cache invalidation.
