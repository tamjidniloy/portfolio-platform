# DEVFOLIO OS Phase 04.2 — Identity & Authorization implementation and approval boundary

**Status (2026-10-23): PARTIALLY IMPLEMENTED security foundations, Candidate security verification passed in CI. NOT owner-approved or ready for public authentication.**

## Architectural review

- Framework: JavaScript ESM, React Router SSR / Express with PostgreSQL.
- Only one owner has login; no visitor signup.
- Single-origin: production session cookies must use `__Host-`, `Secure`, `HttpOnly`, `SameSite=Strict`, `Path=/`, no Domain. Development localhost cookie is differently named and may omit Secure to support HTTP on Windows 11.
- Cryptographic session token: 32 random bytes, base64url in cookie; only SHA-256 digest persists in SQL. Role/status/expiry/revocation checked against database on every lookup; no trust in owner IDs supplied by a browser.
- Session rotation and revocation: PostgreSQL transactions and row locks; replay of rotated tokens fails.
- CSRF: origin equality AND session-bound synchronizer HMAC token on cookie-authenticated state mutations. Generate a high-entropy server-only `CSRF_SECRET` after owner approval; do not expose this secret to frontend code or store it in Git.
- Owner access requires a private runtime-branded session resolved from PostgreSQL; forged plain JS objects do not gain access; private row creator ID must match the authenticated owner ID.

## Unresolved owner decisions / SRS conflict

The historical candidate SRS v1.1 and Phase 03 SQL assumed password + emailed code, but NIST SP 800-63B-4 (https://pages.nist.gov/800-63-4/sp800-63b/authenticators/) expressly prohibits email as an out-of-band authenticator. **Proposed decision**: WebAuthn/passkey as primary owner sign-in, with recovery codes and perhaps password+TOTP fallback subject to owner review. This is only a recommendation. Real WebAuthn requires verified RP ID, allowed HTTPS origin, enrollment/credential storage, user verification, challenge expiry/one-time use and counter/risk handling; do not ship a homebrew approximation. After approval choose a maintained and compatible `@simplewebauthn/server` / `@simplewebauthn/browser` version and test it on native PostgreSQL and browsers. Any Argon2id/password fallback requires an independently reviewed, maintained library and rate-limited real verification.

The current Phase 03.3 candidate DDL's `auth_challenges` and `admin_users.password_hash` are **not the approved final schema**. Do not run final migrations, create an owner identity or claim AAL2 compliance. The active Express/React Router routes intentionally expose **no owner login, registration, challenge, reset, preview or private CMS endpoint**.
