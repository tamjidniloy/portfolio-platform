## Runtime commands

```sh
cp .env.example .env
docker compose up -d postgres
npm install
npm run dev
# GET http://127.0.0.1:3000/ , /healthz , /readyz
npm run check
npm run build
npm run start
```

The `.env` file is ignored by Git. Node 22 is the baseline. `/healthz` reports process liveness even if PostgreSQL is absent; `/readyz` is 503 until PostgreSQL answers `SELECT 1`. Local Compose credentials are disposable development examples only. There are **no migrations**, application tables, owner auth, public content APIs or deployment provisions in 04.0.

## Reproducibility limitation

Direct dependencies are pinned in `package.json`, but a generated `package-lock.json` has not yet been committed. The workflow currently runs `npm install` to exercise the code and this cannot be called a fully deterministic install. Before milestone acceptance, produce and commit a lockfile from a networked trusted environment, change CI to `npm ci`, and rerun checks. Do not mistake a passing CI run under `npm install` for a frozen dependency graph.
