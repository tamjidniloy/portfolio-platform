# Phase 04.5 — Deployment, Infrastructure, Reliability & Observability

**Date:** 2026-10-24. **Scope:** P4-045–P4-053. **Engineering reference status:** implemented in the Phase 04.5 branch; **not provisioned or production-accepted**. This package builds on owner-approved SRS-R1, AUTH-R1, DB-R1, API-R1 and the no-Docker Node 22/React Router SSR system.

## Deployment decision and budget gate (P4-045)

AWS is a **reference implementation, not an approved cloud/vendor purchase**. Terraform under `infra/aws/` provisions an HTTP/HTTPS ALB, one Amazon Linux 2023 Node 22 EC2 host accessible only by Systems Manager (no SSH), private PostgreSQL 16 RDS, private S3 artifact/media buckets, runtime Secret Manager placeholder, CloudWatch logs and alarms, GitHub environment-scoped OIDC deployment role, and cost notifications.

Operator MUST choose and record: AWS vs alternative provider, AWS account ID, region/privacy residency and DPA requirements, hostname/ACM certificate/DNS, paid budget and billing owner, availability target and business RPO/RTO. **Do not run `terraform apply` without actual owner/provider/spend approval.** Terraform is only a deployable candidate for an AWS account the owner controls. A single EC2 host in staging is not high availability; production requires a reviewed capacity/HA/WAF/DDoS, encryption, privacy and threat-model upgrade. The production Terraform switch makes RDS Multi-AZ but DOES NOT make the single application host highly available.

## Immutable release and rollback (P4-048–049)

`.github/workflows/phase045-release.yml` is `workflow_dispatch` only, on `main`, bound to the selected protected GitHub environment. It verifies source and Node build, writes CycloneDX npm SBOM, prunes dev-only packages, creates a tarball with prebuilt Node 22 dependencies, computes SHA-256, and uploads to private S3 at `releases/<environment>/<sha256>.tgz` with a conditional no-overwrite request. GitHub OIDC grants only scoped S3 PutObject and specific EC2 SSM RunCommand. The instance re-verifies the complete artifact SHA, performs a safe path scan, extracts to a content-addressed directory, atomically switches symlink, restarts systemd and checks `/readyz`. On failure it attempts rollback to the previous release and exits nonzero. Post-deploy HTTPS smoke validates health, readiness and anonymous admin denial.

**No automatic migration or owner bootstrap is attached to deployments.** Approval-based, operator-run migration and pre-change backup comes first. Rollback means application revision rollback; incompatible database changes require an explicit forward-fix/restore decision. S3 versioning and SHA naming provide integrity and preservation, not signed provenance/complete supply-chain attestation; add provenance attestations, artifact retention review and independent signatures before production certification.

## Reliability, logging and alarms (P4-050–051)

The Express entrypoint now emits allowlisted structured events only: timestamp, severity, request ID, generic route class, HTTP method, status and duration. It deliberately omits IP, query string, path slugs, email, contact bodies, cookies, tokens and agent strings. `X-Request-ID` is minted independently for every request. CloudWatch Agent captures application, outbox and retention logs; app, service and operator jobs must never print secrets. `/healthz` is process-only; `/readyz` requires DB connectivity. ALB checks readiness and has alarms on unhealthy target, 5xx spikes, EC2 failure and RDS storage. SNS email subscriptions require a human email-confirmation step.

This does **not** claim complete APM/distributed tracing, WAF/rate limiting, SLO uptime measurement, synthetic probes or staffed 24/7 alerting. They require real environment measurements, dashboard/notification tests and an on-call owner. Retention and outbox timers are installed but **NOT enabled** by provisioning: operator reviews policy, DB privileges, e-mail and DLQ monitoring and explicitly enables schedules after acceptance.

## Backups, DR and costs (P4-052–053)

RDS has 30-day automated backups/PITR and encrypted storage, private networking and termination protection in production configuration. `ops/aws/restore-drill.sh` creates an isolated, nonpublic point-in-time restored RDS instance using explicit confirmation. It does not connect to the restored DB or claim integrity. Operator must connect privately, verify version/migrations/schema/sample data and grants, time the incident and record measured RTO/RPO, then authorize cleanup. No automatic production data restore is performed.

AWS Budgets notifies at 80% of `monthly_budget_usd`; alert email/threshold action must be verified. **Budgets are not spending caps** and alerts can lag. AWS pricing depends on region, instance size, ALB, database, storage, egress and email; estimate in AWS Pricing Calculator before approval, verify real billing alarms and set cost limits with the provider. Multi-AZ production, RDS PITR storage and always-on ALB may exceed small personal-portfolio budgets.

## Phase 04.5 production hardening follow-up

The application-layer reference now uses AWS Auto Scaling with **two production application instances across distinct Availability Zones** and a staging single-instance baseline, rather than a permanently single-host production target. It adds an SSM-approved KMS-verified release pointer for autoscaling replacement hosts, rollout to each in-service node, GitHub build provenance attestations, KMS asymmetric signature verification on host, and fails closed if the signature differs. These are reviewed engineering changes; the two-instance deployment, scaling/replacement, rollbacks and AWS KMS verification still need live tests. Release pointer updates happen only when deployment to all existing hosts and public HTTPS smoke succeed. Data and storage systems retain separate review gates.
